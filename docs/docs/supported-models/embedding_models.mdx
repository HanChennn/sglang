SGLang provides robust support for embedding models by integrating efficient serving mechanisms with its flexible programming interface. This integration allows for streamlined handling of embedding tasks, facilitating faster and more accurate retrieval and semantic search operations. SGLang's architecture enables better resource utilization and reduced latency in embedding model deployment.

<Warning>
Native encoder embedding architectures, `google/embeddinggemma-300m`, `nvidia/Nemotron-3-Embed-1B-BF16`, and the BF16 Nemotron-3.5-Embed models are detected automatically. Decoder-style embedding models require `--is-embedding`; add `--trust-remote-code` when the model requires it.
</Warning>

## Quick Start

### Launch Server

```bash
sglang serve \
  --model-path Qwen/Qwen3-Embedding-4B \
  --is-embedding
```

### EmbeddingGemma

EmbeddingGemma uses bidirectional attention and is auto-detected, so its best default command is simply:

```bash
sglang serve --model-path google/embeddinggemma-300m
```

On CUDA, SGLang automatically uses breakable CUDA graph (BCG) for its full encoder prefill and disables incompatible radix-cache and chunked-prefill behavior. Do not add the deprecated piecewise CUDA graph knobs.

### Nemotron-3-Embed

`nvidia/Nemotron-3-Embed-1B-BF16` uses a bidirectional Ministral3 backbone with normalized mean pooling. It is auto-detected from its checkpoint config, so `--is-embedding` is not needed:

```bash
sglang serve --model-path nvidia/Nemotron-3-Embed-1B-BF16
```

It is not supported on ROCm. SGLang disables radix cache and chunked prefill for this model, and skips the KV cache allocation when the prefill attention backend is FA3 or FA4. Prepend the task prefix to each input text as described in the model card, for example `query: ...` or `passage: ...`.

### Nemotron-3.5-Embed

The BF16 1B and 8B checkpoints combine a Pixtral vision encoder, multimodal projector, and bidirectional Ministral3 text backbone. Both use normalized mean pooling over valid text and image positions. The output has 2048 dimensions for 1B and 4096 for 8B. Queries contain text; documents can contain text, images, or both.

On Linux with one NVIDIA CUDA GPU, start the 1B checkpoint with tensor parallelism set to one:

```bash
sglang serve \
  --model-path nvidia/Nemotron-3.5-Embed-1B-BF16 \
  --revision e24ca1e346bcc53572bd7bdc02b3e8ebf66c197c \
  --dtype bfloat16 \
  --tp 1 \
  --host 127.0.0.1 \
  --port 30000
```

For 8B, replace the model path with `nvidia/Nemotron-3.5-Embed-8B-BF16` and the revision with `781e779ee4ca9c2d2a4f38321993556baeab49a1`. Use a GPU with sufficient memory for the checkpoint and image activations. No API key is configured in this example. The checkpoint's retrieval template is loaded automatically; SGLang disables radix cache and chunked prefill for its bidirectional attention.

Use [`/v2/embed`](/docs/basic_usage/cohere_api_embeddings) with `input_type="query"` or `input_type="document"` to apply the checkpoint's task prefix and image-before-text template. Do not add a second prefix to the text. This client requires `requests` and a local `image.png`:

```python
import base64
from pathlib import Path

import requests

url = "http://127.0.0.1:30000/v2/embed"
query = requests.post(
    url,
    json={"texts": ["What is shown in the picture?"], "input_type": "query"},
    timeout=120,
)
query.raise_for_status()

image_url = "data:image/png;base64," + base64.b64encode(
    Path("image.png").read_bytes()
).decode("ascii")
document = requests.post(
    url,
    json={
        "input_type": "document",
        "truncate": "NONE",
        "inputs": [{"content": [
            {"type": "image_url", "image_url": {"url": image_url}},
            {"type": "text", "text": "A technical diagram."},
        ]}],
    },
    timeout=120,
)
document.raise_for_status()
print(len(query.json()["embeddings"]["float"][0]))
print(len(document.json()["embeddings"]["float"][0]))
```

Each `inputs` object produces one vector, combining all of its content blocks. To embed an image alone, use `{"images": [image_url], "input_type": "document"}`. Native `/encode` accepts an already rendered retrieval prompt and the corresponding `image_data`; it does not add the query or document prefix.

The registered accuracy test compares both pinned checkpoints against Hugging Face BF16/SDPA with masked FP32 mean pooling. It covers text, images, combined inputs, multiple images, and batch permutations through `/encode` and `/v2/embed`. Run it on an NVIDIA H100 with FA3 available:

```bash
python test/registered/accuracy/embedding/test_nemotron35_embedding.py
```

<Note>
Both BF16 checkpoints passed numerical validation against the Hugging Face reference on NVIDIA GB200 with tensor parallelism set to one, `trtllm_mha` text attention, and `sdpa` multimodal attention. NVFP4 checkpoints, ROCm, and tensor parallelism greater than one are outside this validation scope.
</Note>

### Client Request

```python
import requests

url = "http://127.0.0.1:30000"

payload = {
    "model": "Qwen/Qwen3-Embedding-4B",
    "input": "What is the capital of France?",
    "encoding_format": "float"  # or "base64" for compact FP32 responses
}

response = requests.post(url + "/v1/embeddings", json=payload).json()
print("Embedding:", response["data"][0]["embedding"])
```


## Multimodal Embedding Example

For multimodal models like GME that support both text and images:

```bash
sglang serve \
  --model-path Alibaba-NLP/gme-Qwen2-VL-2B-Instruct \
  --is-embedding \
  --chat-template gme-qwen2-vl
```

```python Example
import requests

url = "http://127.0.0.1:30000"

text_input = "Represent this image in embedding space."
image_path = "https://huggingface.co/datasets/liuhaotian/llava-bench-in-the-wild/resolve/main/images/023.jpg"

payload = {
    "model": "gme-qwen2-vl",
    "input": [
        {
            "text": text_input
        },
        {
            "image": image_path
        }
    ],
}

response = requests.post(url + "/v1/embeddings", json=payload).json()

print("Embeddings:", [x.get("embedding") for x in response.get("data", [])])
```

## Matryoshka Embedding Example

[Matryoshka Embeddings](https://sbert.net/examples/sentence_transformer/training/matryoshka/README.html#matryoshka-embeddings) or [Matryoshka Representation Learning (MRL)](https://arxiv.org/abs/2205.13147) is a technique used in training embedding models. It allows user to trade off between performance and cost.

### 1. Launch a Matryoshka‑capable model

If the model config already includes `matryoshka_dimensions` or `is_matryoshka` then no override is needed. Otherwise, you can use `--json-model-override-args` as below:

```bash Command
sglang serve \
    --model-path Qwen/Qwen3-Embedding-0.6B \
    --is-embedding \
    --json-model-override-args '{"matryoshka_dimensions": [128, 256, 512, 1024, 1536]}'
```

1. Setting `"is_matryoshka": true` allows truncating to any dimension. Otherwise, the server will validate that the specified dimension in the request is one of `matryoshka_dimensions`.
2. Omitting `dimensions` in a request returns the full vector.

### 2. Make requests with different output dimensions

```python
import requests

url = "http://127.0.0.1:30000"

# Request a truncated (Matryoshka) embedding by specifying a supported dimension.
payload = {
    "model": "Qwen/Qwen3-Embedding-0.6B",
    "input": "Explain diffusion models simply.",
    "dimensions": 512  # change to 128 / 1024 / omit for full size
}

response = requests.post(url + "/v1/embeddings", json=payload).json()
print("Embedding:", response["data"][0]["embedding"])
```
